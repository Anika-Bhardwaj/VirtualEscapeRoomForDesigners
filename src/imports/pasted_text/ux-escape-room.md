Create a premium interactive multiplayer mystery experience called:

"UX Escape Room: The Case of the Missing User"

THIS IS NOT:

- A dashboard
- A product application
- A SaaS tool
- An admin interface
- A training module
- A slide presentation
- A learning management system

THIS IS:

A collaborative digital investigation game inspired by:

- Unsolved Case
- Escape Rooms
- Detective Investigation Boards
- Interactive Mystery Experiences
- Premium Design Workshops

The entire experience should feel like a story-driven mystery where participants recover a missing user perspective before a product launch.

━━━━━━━━━━━━━━━━━━━━

PREMISE

Tomorrow is launch day.

The product has been approved.

The roadmap is complete.

Stakeholders are confident.

Everything appears ready.

But an internal investigation uncovers a troubling discovery.

The user perspective has disappeared.

The original research evidence has been scattered across multiple case files.

Participants are assigned to investigate the evidence, recover critical insights, and find the missing user before the product launches.

Every solved case file reveals a new lead.

Every lead brings the team closer to finding the missing user.

The experience should feel like solving a mystery, not completing training.

━━━━━━━━━━━━━━━━━━━━

AUDIENCE

Primary audience:

Professional designers

Working professionals

Adults with short attention spans

People attending a Design Cafe

Users who enjoy quick wins and teamwork

Not hardcore gamers

Not puzzle enthusiasts

Not escape room experts

The experience should be immediately understandable.

Instructions should be minimal.

Visual communication should do most of the teaching.

━━━━━━━━━━━━━━━━━━━━

EXPERIENCE GOALS

Players should feel:

Curious

Collaborative

Intelligent

Engaged

Rewarded

Surprised

The experience should create moments where participants say:

"Wait..."

"Look at this."

"I found something."

"Try this."

"I think I figured it out."

Avoid creating moments where participants say:

"I don't understand."

"What am I supposed to do?"

"This is too much reading."

Every interaction should satisfy at least one of these goals:

Avoid:

Long text

Complicated mechanics

MULTIPLAYER PRINCIPLES

This is a collaborative experience.

Players should feel like investigators solving a shared case.

If multiple real users are present:

Show presence through real cursor activity.

Do not simulate users.

Do not generate fake cursors.

Do not create AI visitor activity.

If only one participant exists:

Display only that participant.

Collaboration should feel organic.

━━━━━━━━━━━━━━━━━━━━

BOARD STRUCTURE PRINCIPLES

Every room should use a single focused board.

Do not create giant exploration spaces.

Do not create infinite canvases.

Do not hide critical information screens away.

Each room should feel like:

One premium investigation table.

Everything required to solve the puzzle should be visible within the board.

The user should never feel lost.

━━━━━━━━━━━━━━━━━━━━

STORYTELLING PRINCIPLES

The story should unfold through evidence.

Players should learn things by discovering clues.

Every solved puzzle should reveal:

New information

A new lead

A new discovery

A reason to continue

The experience should feel like a connected investigation.

Not separate unrelated activities.

━━━━━━━━━━━━━━━━━━━━

LEARNING PHILOSOPHY

The experience secretly teaches:

Visual Hierarchy

Research Synthesis

Information Architecture

User Behaviour Analysis

Interaction Feedback

However:

Never position the activities as lessons.

Present them as evidence investigations and case-solving exercises.

Players should learn by solving.

Not by reading.

━━━━━━━━━━━━━━━━━━━━

PACE

Target completion time:

15–20 minutes

Puzzle experience should feel fast.

Small wins should occur every 30–90 seconds.

Every room should contain at least one memorable breakthrough moment.
